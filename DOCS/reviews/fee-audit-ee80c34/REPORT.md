| F01 | P1 | Student and teacher sessions can read or submit another same-school student's fees | [Parent fee GET](D:/prototype/app/api/parent/fees/route.ts:23) and [POST](D:/prototype/app/api/parent/fees/route.ts:161) check the parent link only for role `parent`. | F05-G | P1 | Grade resync can reduce a bill below paid plus waived | [Generation resync](D:/prototype/app/api/fees/generate/route.ts:157) uses `GREATEST(new_amount, amount_paid)`, ignoring `waiver_amount`. A ₹1,000 bill with ₹200 paid and ₹600 waived resynced to ₹500 can have ₹800 credited against ₹500 due, with a paid status masking the excess. The separate ledger PATCH coverage guard is fixed on this branch. | Lock the affected bill and reject a grade resync below `amount_paid + active waivers`, or provide an explicit credit/refund adjustment. Test grade change after partial payment plus waiver. |
| F06 | P1 | Ledger PATCH accepts numeric NaN | [PATCH validation](D:/prototype/app/api/fees/ledger/[id]/route.ts:166) compares `Number(new_amount) <= 0`; for `"NaN"` this is false. The later comparison with covered amount is also false and passes the original string to SQL. PostgreSQL `numeric` accepts NaN and treats it as greater than finite numbers ([documentation](https://www.postgresql.org/docs/current/datatype-numeric.html)); the nonnegative constraint cannot exclude it. | Parse and require a finite monetary value with no fractional paise before opening the transaction; add a database guard against special numeric values. Test NaN, Infinity, numeric strings and precision. |
| F07 | P1 | Assignment reduction checks only one period | [Assignment Map](D:/prototype/app/api/fees/category-assignments/route.ts:228) stores multiple monthly bill rows under one `student_id:fee_category_id` key, keeping the last row returned. If April has ₹800 paid and May has zero, reducing the fee to ₹500 can pass if May wins the Map; [the later UPDATE](D:/prototype/app/api/fees/category-assignments/route.ts:254) changes all periods. Query order is unspecified. | Check every existing period, or aggregate maximum committed credit per student/category under the year lock. Test both row orders and mixed paid/waived periods. |
| F08-A | P1 | Removing a variable assignment can erase linked history | [Assignment removal](D:/prototype/app/api/fees/category-assignments/route.ts:286) deletes pending/overdue bill rows with zero `amount_paid` without checking for linked pending/cancelled/rejected payments or revoked waivers. Their foreign keys [cascade on ledger deletion](D:/prototype/lib/db.ts:962). Direct ledger DELETE has been fixed on this branch; this other deletion path remains. | Block deletion when **any** payment or waiver history exists, or retain an audited voided bill. Test each historical status. |
| F09 | P1 | Duplicate-student cleanup can delete paid bills and receipts | In both [bulk](D:/prototype/app/api/students/duplicates/cleanup/route.ts:91) and [selective](D:/prototype/app/api/students/duplicates/cleanup/route.ts:174) paths, an unaliased self-subquery can stop bill reassignment. It remaps payment `student_id`, then [deletes the duplicate student](D:/prototype/app/api/students/duplicates/cleanup/route.ts:106). Unmoved ledger rows cascade away with their payments. The predicate's inner `student_fee_ledger` name is local to the subquery, so it does not unambiguously compare to the outer row. Errors on moves are also swallowed. | Stop student deletion if any financial row remains. Explicitly alias both relations, map or merge conflicting bills, preserve payment/waiver links, and reconcile counts/totals in the same transaction. Test overlapping paid bills on an isolated database. |
| F13-S | P2 | Day-close inputs come from different snapshots | [Mode totals](D:/prototype/app/api/fees/day-close/route.ts:100) and [receipt count/range](D:/prototype/app/api/fees/day-close/route.ts:112) are separate autocommit reads before [the saved close](D:/prototype/app/api/fees/day-close/route.ts:121). | F15 | P2 | Passbook counts amount amendments twice | [Timeline bill event](D:/prototype/app/api/fees/passbook/route.ts:199) starts with current `amount_due`, and [amendment event](D:/prototype/app/api/fees/passbook/route.ts:242) adds historical differences. | F16 | P2 | Carry-only fee categories show a false discretionary waiver | [Category report](D:/prototype/app/api/fees/reports/route.ts:164) uses `discMap.get(c.id) ?? c.total_waived`.
