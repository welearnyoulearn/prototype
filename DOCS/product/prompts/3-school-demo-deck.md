GOAL OF THE MEETING: the principal says "let's pilot this in our school." So sell outcomes, not features. Every feature slide must answer: what pain does this remove, for whom, and what will they see on Monday morning?

DELIVER
1) An editable 16:9 .pptx if you can create files (otherwise HTML slides + a spec): 18–22 main slides plus an appendix (full feature checklist by portal, FAQ, data-safety page).

3) A 25-minute live-demo run-of-show: exact click paths, timings, one "wow moment" per role, and a fallback plan if the internet fails.

STORY

DESIGN DIRECTION: friendly, high-trust, uncluttered. Large real-screen mockups in device frames, before/after comparisons (paper register vs dashboard), colour-coding consistent with the product (green/amber/red = attendance health), one icon per role, big readable type, plain English (plus Telugu headlines if I choose). No jargon on main slides — never say "multi-tenant", "API" or "JWT".

BEFORE YOU ANSWER, self-check: nothing unbuilt is shown as live; every slide names a person and a benefit; a non-technical principal can follow each slide in 5 seconds.
